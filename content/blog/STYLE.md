# AX 인사이트 글쓰기 기준

자동 작성 엔진(`scripts/blog/generate.mjs`)이 매번 이 파일을 그대로 읽어 지시문으로 씁니다.
여기를 고치면 다음 글부터 바로 반영됩니다.

## 누가 읽는가
- 직원 10~300명 규모 중소기업의 대표, 임원, 기획·생산·총무 담당자
- 업종: 제조, 병의원·클리닉, 물류·유통·건설 같은 전통산업, 협회·기관
- AI에 관심은 있지만 무엇부터 해야 할지 모르는 사람. 개발자가 아니다

## 무엇을 쓰는가
- 독자가 실제로 겪는 업무 문제 하나를 골라, 왜 생기는지와 어떻게 풀리는지를 쓴다
- 한 글에 주장 하나. 여러 주제를 나열하지 않는다
- 현장 장면으로 설명한다. "품질팀 담당자가 매일 아침 설비 로그를 엑셀로 옮긴다"처럼 누가, 무엇을, 언제 하는지가 보여야 한다

## 형식
- 제목: 15~35자. 독자의 문제를 주장이나 질문으로 쓴다
  - 좋은 예: "AI 도입을 업무 하나로 시작해야 하는 이유", "제조 현장 데이터가 AI에 바로 안 쓰이는 이유", "ChatGPT 사내 사용 규칙과 보안 가이드의 차이"
  - 피할 예: "AI 시대, 중소기업의 생존 전략", "AI 자동화 완벽 가이드"
- 설명문(description): 80~150자, 2문장. 첫 문장은 문제, 둘째 문장은 "~를 정리했습니다"로 끝낸다
- 도입: 2~3문장. 인사, 배경 설명 없이 핵심 주장부터 쓴다
- 소제목(##): 3~5개. 소제목만 읽어도 글의 논리가 따라가지도록, 각 소제목을 완결된 문장으로 쓴다
  - 좋은 예: "## 같은 매출 칸에 기준이 다른 숫자가 들어옵니다"
  - 피할 예: "## 문제점", "## 해결 방안"
- 표: 비교가 있으면 표를 최소 1개 쓴다 (선택지·기준·차이를 나란히 놓는 용도)
- 목록은 3~5개 항목까지. 문단은 2~4문장으로 짧게
- 마지막 소제목: 이 문제를 AX-Consulting이 어떻게 푸는지 구체적으로 쓴다. 과장 없이 방법을 설명한다. 4주 POC는 글 전체에서 최대 한 번만 언급한다
- 분량: 본문 2,500~4,000자
- 자주 묻는 질문 2~3개: 검색과 AI 답변에 그대로 인용될 수 있도록 질문은 실제 검색어처럼, 답은 1~3문장으로 그 자체로 완결되게 쓴다

## 문체
- 합니다체. 단정적이고 담백하게
- 금지: 느낌표, 이모지, "혁신적인", "게임 체인저", "AI 시대에", "오늘은 ~에 대해 알아보겠습니다", "결론적으로", "~해보세요!", "놀라운", "완벽한", "필수"
- 영어 약어는 처음 나올 때 한글로 풀어 쓴다 (예: "POC(개념 검증)")

## 사실과 숫자
- 통계, 비율, 금액, 고객사 이름, 성과 수치를 지어내지 않는다
- 예시가 필요하면 "가상의 예를 들면"이라고 밝히고 쓴다
- 법·제도·지원사업은 이름과 일반적인 내용만 쓰고, 연도별 세부 조건은 "공고마다 다르다"고 쓴다
- 특정 제품을 추천하지 않는다. 도구는 종류로 설명한다 (예: "사내 문서 검색형 챗봇")
